# 门店操作规范（SOP）

本文件只收系统依赖、但系统不检测或不强制的操作规范。系统行为见 [domain.md](domain.md)。
涉及补录入口和工作站的步骤随补录入口、工作站交付生效（尚未实现，见 domain.md「时间」补录、「命令提交与结果未知」）。

系统保证记录可追溯：每条记录保存操作人、设备、门店节点收到它的时间（`recorded_at`）和声明的发生时间（`occurred_at`），纠错只追加、不覆盖原记录。
系统不保证记录真实，真实性靠本规范和店长复核。

## 账号

- 只用自己的 PIN 登录，不告诉他人，不替他人登录。
- 离开平板前登出。
- 登出时提示有后台任务未完成：能去工作站的选【取消】，按「后台任务与工作站核对」处理后再登出；不能时把提示中列出的内容抄到系统中断登记本（点过提交：是），再选【确认登出】。
- 下一班发现上一班没有登出时，报告店长并记入登记本；平板上有未完成的后台任务时由店长按「后台任务与工作站核对」处理；再登出，换自己的身份登录。（随认证切片生效）

## 记录

- **当场记录**：业务发生时由本人在平板上录入，不替他人录入，不在班末集中录入。
- 平板提示「未发出」时，换一台能连上的平板重录，或记到系统中断登记本，照抄屏幕上的内容。
- 平板提示「已交给后台任务」时，不记纸面，也不在别的平板重录。
- 顶部显示连不上门店机时，新记录直接换平板录入或记纸面。
- 每次用平板时看一眼顶部计数。「需处理」变红时，自己的任务当场处理；不是自己的，告诉录入人或店长。
- 事后才录入的，走补录入口（平板或工作站），如实填写发生时间，并向当班店长说明原因。
- 提交收货、生产、报损等单据前，核对界面显示的发生日期和时间；与实际不符时不要提交，告知店长检查门店节点和平板的时钟。
- **录错**：用纠错入口（数量更正或整条冲销）并写明原因。不得另录一条反向记录来抵消。
- **温度记录**：只记录实际测得的温度。到点没测就是漏测，告知店长，不得事后补成按时测量。记在系统中断登记本上的温度，恢复后走补录入口转录。

## 数量

- 每次录入的数量不超过 9999.999。数量可能超过 9999 的物料，由店长在主数据中定义更大的单位（如 kg、袋、箱），员工按大单位录入。
- 进口物料按包装上的单位录入（如 oz、lb），换算系数在主数据中按标准值填写（1 oz = 28.349523125 g，1 lb = 453.59237 g）。

## 批次标签

- 批次标签只在收货或生产提交成功后打印，标签上的批次号以成功结果为准。提交结果未知时，货物先放待贴标签区；后台任务完成后按通知打印，或在工作站核对为已入账后按批次号打印；不另行录入。
- 标签损坏或脱落时，按批次号重打原标签，不新建批次。
- 生产商批号是包装上原有的号，不能代替批次号。

## 生产

- 取料前在平板上点「开始生产」。没点时，生产期间发生的盘点不会吸收这次用料，盘点差异会算错。

## 报损

- 系统提示需要确认（如账面不足）时，先核对实物，确认确实报损了这么多再确认。不要为了让提交通过而确认。
- 发现数量、物料或批次录错时，改正后重新预检，再确认。

## 盘点

- 盘点前确认各平板没有「进行中」或「需处理」的后台任务。
- 只数货架上的实物，不含在制品。
- 盘点单上额外补加的批次号，必须来自已经完成的收货或生产登记。不能为了提交盘点在盘点中创建批次，也不能把实物随便归入某个已有批次。
- 发现尚未完成收货或生产登记的实物：暂停该物料的盘点，先完成登记（补录收货或生产），再重新清点该物料；不能把它混入已有批次的清点数。
- 来源不明、无法登记的实物：隔离存放，由店长决定查明来源后登记，或者丢弃且不在系统中记录报损。不能用不指定批次的报损去扣其他已知批次。
- 从开始清点到提交，被盘物料不得领用、收货、报损或生产取料。
- 违反时盘点差异会算错，由店长重盘。
- 盘点提交结果未知、工作站核对为没有收到时，先在平板取消这条任务，再重新清点，用新命令提交。

## 门店机校时

- App 提示「门店机需要校时」时，店长在门店机附近打开手机的无线热点（部署时登记的那部手机）。门店机自动连上并校时；之后员工再点一次提交，记录照常入账。恢复后可以关闭热点。
- 等待期间可以查询，不能录入。打开热点几分钟后仍未恢复，或没有可用的手机时，改用系统中断登记；网络恢复后走补录入口补交，按纸面填写发生时间。
- 更换店长手机，或修改热点名称、密码时，通知负责门店机维护的人重新登记。
- 禁止手动修改门店机、平板和手机的时间。发现时间不对时告诉店长：门店机按本节打开热点自动校时，平板和手机在 App 中点「校时」。
- 门店机日志出现状态文件写入、删除或 fsync 错误时，维护门店机的人修复存储后先删除状态文件再启动服务，确认门店机重新校时成功后再通知店长恢复录入。
- 员工在附近没有人盘点时收到「被盘点吸收」的提示，告诉店长，由店长按本节核对门店机时间。

## 门店机地址与证书

- 不自行重置或更换门店路由器，不修改门店机、平板、手机和标签打印机的网络设置。需要时联系维护门店机的人，按部署记录恢复各设备的固定 IP。
- App 提示连不上门店机（网络不通或证书无效）时，新记录按「记录」换平板录入或记纸面，并告诉店长；店长联系维护门店机的人。
- App 提示门店机有问题需要处理时，店长联系维护门店机的人。
- 门店机更换或重装后，维护人员更新平板的门店机证书配置（经设备管理下发）并确认平板能连上之前，按「门店节点宕机」处理。

## 门店节点宕机

- 改用系统中断登记。工作站同样不可用。
- 节点恢复后先按「意外后二次校验」处理，再按登记本逐条补录。

## 后台任务与工作站核对

- 顺序固定：
  1. 在工作站用扫码枪扫平板上的任务二维码（扫码枪故障时手输完整任务编号），按编号核对。
  2. 到平板处理这条任务：显示「完成」→ 已入账，不补录；仍为「进行中」或「需处理」→ 在平板上取消。
  3. 第 1 步答「没有收到」的，取消之后才在工作站补录，照平板上的任务内容填写。平板不在手边或没电时先不补录，拿到平板、取消之后再补。
- 核对为已入账的收货、生产，按核对结果中的批次号打印标签。
- 盘点不补录：取消之后重新清点，用新命令提交。
- 不在纸上抄任务编号。
- 检查点：交班前、闭店前、盘点前，店长查看各平板的「进行中」和「需处理」，按上面的顺序处理。

## 系统中断登记

- 适用：平板提示未发出、门店节点宕机、门店机校时失败、员工登出时选【确认登出】。
- 门店备一本系统中断登记本，每行一条记录，栏目：

  | 栏 | 说明 |
  |---|---|
  | 发生时间 | 业务实际发生的时刻，精确到分钟；照抄平板失败页或登出提示显示的时间（没用平板时按实际） |
  | 类型 | 收货 / 生产 / 报损 / 温度 |
  | 物料（或设备） | 物料名称和编码；温度记录写设备 |
  | 数量与单位 | 按包装上的单位写，例如「2 袋 × 25 kg」 |
  | 批次号 | 报损指定了批次时照标签写；收货、生产在补录成功后再打标签，补录后填 |
  | 原因 / 供应商 | 报损写原因，收货写供应商 |
  | 记录人 | 签名 |
  | 点过提交 | 是 / 否。未发出、没用平板时为「否」；选【确认登出】时从登出提示抄下的任务为「是」（原请求可能已入账） |
  | 补录人与补录时间 | 补录成功后填；补录提示疑似重复、核对后判定为已入账而不补录的，写「已入账（事件 …）」 |

- 补录顺序：先按「后台任务与工作站核对」处理各平板上未完成的后台任务；再按登记本逐行补录，按发生时间先后。
- 补录提示疑似重复时：看「点过提交」一栏，对照匹配记录中的操作人、设备和时间，判断是否就是同一件事；拿不准时问店长。不要为了让补录通过而确认。

## 意外后二次校验

- 发生意外（设备故障、门店节点宕机、长时间断网等）之后，店长检查工作站和各平板的后台任务，做二次校验：各平板上未完成的任务按「后台任务与工作站核对」处理；登记本上的行都已补录或写明已入账；补录的记录在复核中核对。

## 复核

- 店长复核：录入时间明显晚于发生时间的记录、被盘点吸收的记录、纠错、盘点差异、报损，以及补录的记录，特别是确认过疑似重复的。
- 复核的频率与形式见 [domain.md](domain.md) Q11。
